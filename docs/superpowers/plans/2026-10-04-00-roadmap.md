## Catatan wajib untuk rencana tahap berikutnya (dari review Tahap 0)

**SvelteKit 3** (bukan 2 seperti asumsi awal): konfigurasi di `vite.config.ts` (`sveltekit({...})`), impor `#lib/...` selalu dengan ekstensi file, env lewat `src/env.ts` + `$app/env/public`, hash router → rute aktif pakai `routePath(page.url)`, tanpa `+layout.ts`.

**Supabase Auth**: `auth.admin.createUser` meng-INSERT user lalu meng-UPDATE `app_metadata`; profil dibuat trigger dari `app_metadata` (migrasi 0003). Harness tes PGlite meniru urutan ini — jaga tetap begitu. Migrasi yang sudah di-push (0001–0003) tidak boleh diubah; perubahan = migrasi baru.

**Tahap 1 (kelola akun)**:
- Batasi kolom yang bisa diubah admin lewat API (`id`, `username` jangan), atau lewat Edge Function service-role.
- Cegah admin terakhir menurunkan/menonaktifkan dirinya sendiri.
- Menonaktifkan akun juga mem-*ban* user di Auth (`ban_duration`) supaya refresh token berhenti.
- Jangan pernah memutuskan hak akses dari `app_metadata` di JWT (bisa basi); selalu dari tabel `profiles`.
- Hapus akun lewat `auth.admin.deleteUser` (profil ikut terhapus).

**Sebelum Tahap 2 (jualan)**: `AuthState` sekarang mengeluarkan pengguna bila profil gagal dimuat (mis. internet putus saat token diperbarui tiap jam). Harus diubah: simpan profil/outlet di perangkat, anggap "siap (offline)" bila sesi masih sah, coba lagi saat online. Ini juga syarat Tahap 4.

**Dari review Tahap 1 (wajib untuk Tahap 2–3):**
- Menu, bahan, dan satuan beli tidak bisa dihapus (hanya nonaktif). Tabel transaksi/stok baru wajib `on delete restrict` ke tabel master.
- Resep hanya boleh bahan aktif `mode = 'otomatis'` (dijaga `simpan_resep`). Pemotongan stok di Tahap 3 hanya dari resep.
- Data master/harga: hak tabel diberikan eksplisit di migrasi (project baru tidak otomatis memberi hak); anon tidak punya hak apa pun.
- Simpan dari UI: pakai `antrianTerakhir` (per kolom) / `rantai` (per baris data) agar tidak saling menimpa.
- Harga beli & data bisnis hanya di aplikasi atau `data/*.local.json`; `tests/rahasia.test.ts` menjaga.
- Aturan resep dijaga trigger (0007): baris resep hanya bahan aktif & otomatis; bahan yang dipakai resep tidak bisa dinonaktifkan/diubah mode. Outlet tidak bisa dihapus.
- Tahap 2 (kasir): saring menu `aktif`; menu baru butuh migrasi + baris harga_jual per outlet (belum ada UI tambah menu); harga 0 untuk pelengkap itu sah.
- Tahap 3 (stok): 12 porsi/kg disimpan 0,0833 kg (12 porsi = 0,9996 kg) — opname harus toleran; kolom stok minimal 4 desimal; akun yang sudah bertransaksi jangan dihapus (FK restrict) — cukup nonaktif.
- Riwayat git berisi harga beli lama: owner memutuskan dibiarkan (harga stokis tidak rahasia, 4 Okt 2026).
- **Tahap 5/7 — modal tepung:** ikuti rumus di spesifikasi §4 "Modal tepung (rumus wajib)": campuran 50:50 menurut berat, harga per kg per jenis, pemakaian dalam kg per jenis dari stok awal + beli − opname (bukan per karung, karena ukuran karung beda 20 vs 25 kg), modal per potong = Σ(kg × harga/kg) ÷ (potong ayam + porsi kulit), plus peringatan bila rasio menyimpang dari 50:50.
